백엔드를 맡아 프로젝트를 진행하며 API 문서를 작성해야 하는

## API

> 프로그램/어플리케이션 간에 요청과 응답을 통해 데이터를 주고받기 위한 수단/규칙

### API가 필요한 이유?

1. 모듈화
   API를 통해 백엔드를 모듈화하여 재사용 가능한 형태로 제공할 수 있다.
2. 클라이언트와의 분리
   클라이언트와 서버를 독립적으로 개발하여

3. 다양한 플랫폼
   서로 다른 플랫폼(모바일 앱, 웹 앱 등) 및 기술을 사용하는 프로그램끼리 통신할 수 있다.

## API 명세서란?

> api가 소프트웨어와 어떻게 상호작용하는지에 대한 설명서. URL, 요청/응답 데이터 형식, HTTP메소드, 헤더, 에러 코드와 대응방안, 상태 코드 등을 포함한다.

- 명확하고 일관성이 있어야 한다.
- 표준화된 명세로 소프트웨어의 이해를 돕고, 테스팅 및 디버깅 등에 활용된다.

## RESTful API

> API작동 방식에 조건을 부과하여, 두 시스템 또는 소프트웨어가 안전하게 정보를 교환하기 위해 사용하는 인터페이스.

- 쉽게 구현하고 수정할 수 있어

`REST`(Representational State Transfer) : API 작동

## 그 외 API

- GraphQL
  - 클라이언트가 필요한 데이터를 요청
  - 클라이언트가 데이터 구조를 지정하기 때문에 불필요한 데이터를 받지 않을 수 있다.
- Webhooks
  - 이벤트가 발생할 때 특정 URL로 HTTP 요청을 보내는 방식
  - 비동기적 이벤트 처리에 유용
- WebSocket
  - 실시간 양방향 통신을 지원
