## ISA (instruction set architecture)

서로 다른 컴퓨터는 다른 instruction set을 가진다.
해당 수업에서는 MIPS 아키텍처를 통해 하드웨어와 소프트웨어 인터페이스를

## MIPS

- RISC-V 계열의 명령어 집합(ISA)이다.
- Big-endian (0x12345678은 메모리에 0x12 0x34 0x56 0x78)

## MIPS의 design principle

1. simplicity favors regularity

- 모든 `arithmetic operation`은 3개의 operands (2source, 1destination)을 가진다.
- lw, sw는 2레지스터와 1개의 상수를 사용한다.

2. smaller is faster

- MIPS는 적은 수의 레지스터를 갖는다.
- (32bit x 32개 (0~31)의 레지스터)
- 따라서 적은 수의 레지스터로부터 데이터를 획득하는 것이 많은 수의 레지스터를 사용하는 것보다 빠르다.

3. Good design demands good compromises

- 여러 명령어 format(R,I,J)은 명령어 디코딩을 복잡하게 만들지만, 가능한 한 format간 유사성을 유지한다면 이를 완화할 수 있다.

(MIPS 레지스터 사진)

## register operands

> arithmetic operation은 레지스터를 피연산자로 사용한다.

`$t0`~`$t9` : temporary 값
`$s0`~`$s7` : saved variables

- `register optimization` : 더 빠른 속도를 위해, 컴파일러는 레지스터변수를 최대한 많이 사용하여야 한다. (자주 사용되지 않는 변수들을 메모리에 저장한다.)

## memory operands

- arithmetic operation은 레지스터에서만 실행되기 때문에, 메모리의 LOAD, STORE가 필요하다.
- 메인메모리는 arrays, structures, dynamic data 등 데이터의 집합체가 존재한다. 레지스터에는 base address (시작 주소)가 저장되고, offset

## Immediate operands

- 빼기 immediate instruction 대신 음수를 사용한다.
- load명령어를 사용할 필요를 없애준다. ->

## MIPS instruction format

1. `R format` 레지스터 간 연산
> opcode rs rt rd shamt function
> add, sub, and, or, nor, sll, slr

- opcode(0)는 R형 명령어임을 나타내고, function은 그 중 어떤 연산인지를 나타낸다.
- rs, rt는 피연산자 레지스터 번호(0~31)가 들어가고,
- rd에는 값을 저장할 레지스터 번호(0~31)가 들어간다.

- 어셈블리어는 `add rd rs rt`와 같이 순서가 다름을 주의.


1-1.add
> add $rd, $rs, $rt
- opcode : 0
- rs + rt를 해서 rd에 저장한다.
- shamt : 0 (사용되지않음)

1-2.sub
> sub $rd, $rs, $rt
- opcode : 0
- rs레지스터 - rt레지스터의 값을 rd레지스터에 저장

1-3.and (bitwise)
> and $rd, $rs, $rt
- opcode : 0
- rs와 rt레지스터의 값을 비트단위로 and연산 하여 rd에 저장

1-4.or (bitwise)
> or $rd, $rs, $rt
- opcode : 0
- rs와 rt레지스터의 값을 비트단위로 or연산 하여 rd에 저장

1-5.slt
> slt $rd, $rs, $rt
- opcode : 0
- rs가 rt값보다 작으면 rd에 1을 저장 (그렇지 않으면 0 저장)


1-6.sll (shift left logical)
> sll $rd, $rt, shamt
- 2의 제곱수를 곱하는 것과 같다.(곱셈을 더 빠르게 계산할 수 있다.)
- rt레지스터의 값을 왼쪽으로 shamt(bit)만큼 시프트하고, 그 값을 rd에 저장한다.
- rs값은 0


1-7.srl (shift right logical)
> srl $rd, $rt, shamt
- 2의 제곱수를 나누는 것과 같다. (나눗셈을 더 빠르게 계산할 수 있다.)
- rt레지스터의 값을 오른쪽으로 shamt(bit)만큼 시프트하고, 그 결과를 rd에 저장한다.
- rs값은 0

2. `I format` immediate값을 사용하는 경우
   > bne, beq, lw, sw, andi, ori

- common case 최적화
- 복잡도 증가
- immediate 산술/load,store 명령
- R format과 달리 `rt`가 목적/소스 레지스터
constant : -2^15 ~ 2^15-1
address : rs의 base address에 더해질 offset


2-1.lw
> lw $rt, offset($rs)
- 메모리에서 rs레지스터의 주소 + offset에 위치한 곳의 word를 rt에 로드한다.
- opcode : 35


2-2.sw
> sw $rt, offset($rs)
- rt레지스터의 값을 메모리의 rs레지스터의 주소 + offset에 저장한다.
- opcode : 43


2-3.beq
> beq $rs, $rt, offset
- rs와 rt레지스터의 값이 같으면, offset으로 분기한다.
- opcode : 4


2-4.bne
> bne $rs, $rt, offset
- rs와 rt레지스터의 값이 다르면, offset으로 분기한다.
- opcode : 5


2-5.ori (bitwise)
> ori $rt, $rs, immediate
- rs레지스터 값과 immediate값을 비트단위 or연산하여 rt에 저장
- opcode : 13



2-6.addi
> addi $rt, $rs, immediate
- opcode : 8
- rs레지스터값과 immediate값을 더해 rt에 저장한다.

3. `J format` 

3-1.j
> j target
- 명령어의 실행 흐름을 target주소로 점프한다.
- opcode : 2
- 아무 주소로나 jump가 가능한 것은 아니고, 하위 비트가 1111...일 때 PC+4로 상위 4비트가 변경됐을 경우 범위를 초과하여 점프 불가능해지는 경우가 있을 수 있다.

> jal target
- 명령어의 실행 흐름을 target주소로 점프하고, 현재 명령어의 다음 주소를 ra 레지스터에 저장
- opcode : 3




## control unit
> opcode(instruction[31-26])를 통해 다음의 값을 결정한다.
신호 이름 :	인가되지 않은 경우(0)  &  인가된 경우 (1)
`RegDst`	rt가 Write register 가 된다 &	rd가 Write register가 된다
`RegWrite`	Nothing	& Write register에 Write data 를 쓴다
`ALUSrc`	Read data2가 ALU의 두 번째 operand가 된다	& 하위 16비트(instruction[15:0])가 sign extend된 값이 ALU의 두 번째 operand가 된다
`ALUOP` 수행 연산 종류
`PCSrc`(branch && zero)	PC + 4가 새로운 PC값이 된다	& branch target이 새로운 PC 값이 된다.
PC + 4 + target
`MemRead`	Nothing	& address 입력이 지정하는 데이터 메모리 내용을 Read data 출력으로 내보낸다 (???)
`MemWrite`	Nothing	& address 입력이 지정하는 데이터 메모리 내용을 Write data 입력 값으로 바꾼다
`MemtoReg`	ALU 출력이 레지스터의 Write data 입력이 된다	&  데이터 메모리 출력이 레지스터의 Write data 입력이 된다
