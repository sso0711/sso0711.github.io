## Pipelining
> Pipelining이란, 동시에 실행 가능한 명령어를 중첩시켜 처리함으로써 throughput을 올리는 것을 의미한다.

- 각 단계의 수행 속도는 그대로이다.
- 다음과 같은 상황에서 각 명령어가 다음 clock cycle에 실행되지 못하는 hazard가 발생하며, 
    - 데이터에 의존성이 있을 때 즉, 이전 연산의 결과를 다음 명령어에 사용할 때
    - branch instruction


## Hazard
> 각 명령어가 다음 클럭 사이클에 실행되지 못하는 상황

### 1.구조적 hazard
명령어의 조합을 하드웨어가 지원하지 못함.
-> 설계자가 파이프라인을 설계하는 시점에서 이를 피하도록 한다.

### 2.data hazard
> 앞선 명령어에 종속성을 가질 때, 다른 단계가 끝나기를 기다려야 하기 때문에 발생

[해결방법]
전방전달(forwarding)
우회전달(bypassing) : 별도의 하드웨어를 추가하여 값을 일찍 받아옴 (데이터패스를 추가로 하드웨어로 연결하여 내부 버퍼로부터 가져옴) 데이터가 레지스터에 쓰여지기 전에 비트값으로 값을 받아옴.

`적재 사용 데이터 해저드` 데이터 적재 명령어를 사용하는 경우, 4단계로 시간이 오래 걸린다. 
파이프라인 지연의 대표적인 예


### 3. control hazard (branch hazard)
> 한 명령어의 결과값에 따라 다른 명령어들이 실행될 떄


[발생요인]
3-1.branch instruction
- ID stage에 오면 stall이 발생할 수 있다고 판단
- EX stage에 수행된다고 하면 이 시점에서 다음 instruction을 결정해서 가져옴 -> 두 개의 instruction이 stall될 수 있으므로 더 이른 시점인 ID에서 판단.
- 
3-2.exception

[해결방법]
1.지연 : 순차적으로 작업을 반복한다. 그러나 큰 속도 저하를 초래한다.
2.예측 : 분기가 항상 실패한다고 예측한다. 
3.분기 지연 : 분기가 필요한 명령어의 결과값이 나오는 동안 이와 관련없는 다른 명령어를 먼저 실행한다. ->컴파일 최적화를 통해 이루어짐
